1. System Overview & Architecture

Hijin is an autonomous desktop artificial intelligence workbench engineered specifically for financial audit, reconciliation, and compliance workflows. Unlike browser-based cloud AI tools that transmit confidential accounting data across public networks, Hijin executes directly on your local Windows operating system.

The Four-Tier Architecture

Hijin maintains strict physical separation across four distinct application boundaries:

  1. Tauri 2 Native Presentation Layer: Lightweight 35.1 MB unpacked desktop shell with native Windows hardware acceleration and negligible baseline RAM footprint (~142 MB).
  2. Rust Daemon Background Sidecar (hijin_daemon.exe): Manages local process lifecycle, memory-mapped tensor IO, local SQLite database indexing, and asynchronous IPC.
  3. Deterministic Python Calculation Sandbox: Operates completely decoupled from token prediction. Mathematical calculations execute strictly through Python decimal.Decimal routines to eliminate floating-point drift.
  4. Dual-Core Neural Inference Engine: Streams and loads quantized GGUF weights locally via GPU offload (CUDA / ROCm / Vulkan) or multi-threaded CPU AVX2 instructions.

3. Windows Installation Guide

The desktop release is packaged into a compact 6.58 MB NSIS setup executable: Hijin_Setup_1.0.0.exe.

Command-Line Installation Options

System administrators can deploy Hijin silently across enterprise fleets via PowerShell:

PowerShell Silent Deployment Administrator 
# Download installer
Invoke-WebRequest -Uri "https://github.com/Aktnyl/Hijin-AI/releases/download/v1.0.0/Hijin_Setup_1.0.0.exe" -OutFile "$env:TEMP\Hijin_Setup.exe"

# Execute silent installation
Start-Process -FilePath "$env:TEMP\Hijin_Setup.exe" -ArgumentList "/S" -Wait

Windows SmartScreen Notice

Because Hijin v1.0.0 is a newly released desktop binary, Windows Defender SmartScreen may display an informational screen: "Windows protected your PC". Click More info and select Run anyway. You can verify binary authenticity against the published SHA-256 hash at any time:

Integrity Check
Get-FileHash -Path "$env:USERPROFILE\Downloads\Hijin_Setup_1.0.0.exe" -Algorithm SHA256

6. Reconciliation Engine & Fixed-Point Math

Hijin performs two-way and three-way reconciliation between:

  • Vendor Invoices: Scanned or digital PDFs, extracting subtotal, taxes, line items, and PO reference numbers.
  • Purchase Orders: Authorized procurement batches with unit prices and quantity limits.
  • Bank Settlements: Cleared cash transactions exported via CSV or OFX feeds.

Deterministic Decimal Implementation

In standard floating-point arithmetic (IEEE 754), 0.1 + 0.2 = 0.30000000000000004. In financial accounting, this rounding error compounds into severe ledger variances. Hijin calculates all amounts using Python's decimal.Decimal initialized from string literals, preserving exact penny values:

Fixed-Point Engine
from decimal import Decimal

# Deterministic calculation guaranteed
subtotal = Decimal('4250.00')
tax_rate = Decimal('0.0825')
tax_amount = (subtotal * tax_rate).quantize(Decimal('0.01'))  # Decimal('350.63')
total_calculated = subtotal + tax_amount                      # Decimal('4600.63')

7. Ed25519 Cryptographic Licensing & Offline Grace

Hijin utilizes an asymmetric Ed25519 public-key signature system for license verification. When you purchase a subscription or generate an evaluation key, our licensing server issues a cryptographically signed token:

Signed Token Structure
{
  "licensee_id": "cpa_88124_sarah",
  "tier": "financial_specialist",
  "valid_until": 1790899200,
  "hardware_hash": "a4f8...9b2c",
  "offline_grace_seconds": 604800,
  "signature": "3e9b...1f0a"
}

The local application verifies the signature against our embedded public key. If the system is offline, the token remains valid for up to 7 full days (604,800 seconds) before requiring an online check-in.

8. Security, Privacy & Forensic Audit Provenance

Accounting compliance requires incontrovertible proof for every number presented to an auditor. Whenever Hijin flags a variance or matches an invoice, it records:

  • Exact PDF page index and vector bounding box coordinates [x, y, w, h].
  • SHA-256 fingerprint of the source document file.
  • Calculation timestamp and mathematical proof trace.

These provenance anchors are compiled into the exported Forensic Audit Discrepancy PDF Brief, providing CPA audit defense documentation that satisfies external regulatory review.
